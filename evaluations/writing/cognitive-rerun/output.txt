# Delivery guide

## Delivery stages

- **Ingestion:**
  - The ingestion endpoint accepts a message after the message reaches the queue.
  - The message has not reached storage when the endpoint accepts it.
  - The endpoint rejects messages larger than 128 KiB.

- **Storage:**
  - A worker attaches a sequence number to the message.
  - The worker writes the message to storage.

| Write result        | Worker action                                                    |
| ------------------- | ---------------------------------------------------------------- |
| The write succeeds. | The worker acknowledges the queue only after the write succeeds. |
| The write fails.    | The worker retries the write.                                    |

- **Search indexing:**
  - The indexer then updates search separately.

## Tenant identification and duplicates

- **Tenant identification:**
  - A tenant key identifies the tenant at ingestion.
  - Storage keys include the tenant ID.
  - Search checks the tenant key before querying.

- **Duplicate handling:**
  - Duplicate handling depends on whether the message has a message ID.

| Message ID            | Duplicate handling                                                  |
| --------------------- | ------------------------------------------------------------------- |
| A message ID exists.  | Duplicate messages within the same tenant are discarded for 7 days. |
| No message ID exists. | Client retries can create duplicates, and duplicates can remain.    |

## Search timing and customer guidance

- **Search availability:**
  - Some readers mistakenly treat acceptance as search availability.
  - The measured search delay in the local test is 5 seconds.
  - Production timing is unknown.

- **Customer guidance:**
  - Operators must not tell customers that production search delay is always 5 seconds.

## Inspection and ownership

```bash
deliverctl inspect --message "sample 3"
```

| Stage | Owner |
| --- | --- |
| Queue | Intake |
| Store | Worker |
| Search | Indexer |

# Delivery guide
Our ingestion endpoint accepts a message after it reaches the queue, but it has not reached storage at that time. The endpoint rejects messages larger than 128 KiB. A worker attaches a sequence number, writes the message to storage, and acknowledges the queue only after the write succeeds. If the write fails, the worker retries it. The indexer then updates search separately. The measured search delay in the local test was 5 seconds; production timing is unknown. Some readers mistakenly treat acceptance as search availability.
A tenant key identifies the tenant at ingestion. Storage keys include the tenant ID. Search checks the tenant key before querying. Duplicates are possible if the client retries without a message ID. If a message ID exists, duplicate messages within the same tenant are discarded for 7 days. If no message ID exists, duplicates can remain. Operators must not tell customers that production search delay is always 5 seconds.

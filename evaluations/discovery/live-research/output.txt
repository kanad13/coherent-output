**Recommendation: use a local Python substring scan first. Verdict on adding FTS5: COUNTER-PROPOSAL.** Your search requirement is real, but with 800 notes, one user, no latency problem, and two hours available, an index adds work without a demonstrated benefit.

I interpret “any substring” as including one- and two-character queries and treating search input literally.

| Verified finding | Implication | Primary source |
| --- | --- | --- |
| Default FTS5 searches tokens; prefix queries match token beginnings. | Searching `ell` does not find `Hello`. | [SQLite FTS5](https://www.sqlite.org/fts5.html) |
| FTS5’s trigram tokenizer supports internal substrings and defaults to case-insensitive matching. Its full-text queries do not match substrings shorter than three Unicode characters. | Trigram `MATCH` alone fails your “any substring” requirement. | [SQLite trigram documentation](https://www.sqlite.org/fts5.html#the_trigram_tokenizer) |
| Trigram tables support `LIKE`, with a scan fallback for patterns without usable trigrams. SQLite’s default `LIKE` folds ASCII case only; `%` and `_` are wildcards. | `LIKE` can cover short queries, but literal input and Unicode case handling need care. | [SQLite FTS5](https://www.sqlite.org/fts5.html), [SQLite expressions](https://www.sqlite.org/lang_expr.html#like) |
| Python `str.casefold()` supports caseless matching, including converting `ß` to `ss`. | Casefolding both the query and note text provides an explicit Unicode matching rule. | [Python string documentation](https://docs.python.org/3/library/stdtypes.html#str.casefold) |

Synthetic, in-memory checks on SQLite 3.53.4 confirmed these distinctions: trigram `MATCH` found `ELL` in `Hello`, missed `e` and `el`, and did not equate `strasse` with `Straße`. Python casefolded containment matched all those examples. These checks establish behavior in this test runtime, not performance on your notes or compatibility with your app’s runtime.

The trade-off is straightforward: a scan supports arbitrary query lengths with one matching path and keeps processing local. Trigram FTS5 offers potential speed for longer queries, but adds index setup, update consistency, query handling, and short-query behavior to maintain. Given your constraints, correctness has higher immediate value than indexing. Scan performance remains an inference until measured against the actual corpus.

The ingest worker receives uploaded CSVs. It checks required columns before sending records to the queue. A rejected upload never enters the queue. Valid records include tenant ID and a deduplication key. Queue messages can be delivered twice and are delivered in no guaranteed order. The database writer deduplicates by tenant ID plus deduplication key; neither key alone is sufficient. Acknowledgment occurs only after the database commit. A crash before acknowledgment can cause another delivery. Search indexes are updated asynchronously from committed records. Typical indexing delay is 30 seconds; there is no guaranteed upper bound. Customer support often mistakes indexing delay for failed upload. WARNING: Never delete source uploads based only on an empty search result. The database is the durable record; the index is a view. Before replaying records, confirm tenant ID and deduplication key. Source upload retention is 7 days. Audit logs record rejection, commit, and index events.

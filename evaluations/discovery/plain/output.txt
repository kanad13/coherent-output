# From CSV upload to search

An uploaded CSV passes through four parts: the ingest worker checks it, the queue carries valid records, the database writer commits them, and the search index makes committed records searchable. Index updates happen asynchronously, so a record can be stored successfully before it appears in search. The database is the durable record; the index is a view. Audit logs record rejection, commit, and index events so support can trace this path.

WARNING: Never delete source uploads based only on an empty search result.

## How records move through the system

The ingest worker receives uploaded CSVs and checks required columns before sending records to the queue. A rejected upload never enters the queue. Valid records include a tenant ID and a deduplication key.

Queue messages can be delivered twice and arrive in no guaranteed order. The database writer deduplicates using tenant ID plus deduplication key; neither key alone is sufficient. It acknowledges a message only after the database commit. A crash before acknowledgment can cause another delivery, which makes this combined identity essential when processing records again.

Search indexes update asynchronously from committed records. The typical indexing delay is 30 seconds, but there is no guaranteed upper bound. An empty search result therefore cannot establish that an upload failed. Customer support often mistakes this delay for a failed upload.

## How to investigate a missing search result

1. Check audit logs for rejection, commit, and index events. A rejection explains why the upload never reached the queue; a commit establishes that the record reached the durable database.
2. If the record committed, consider indexing delay when investigating its absence from search. Do not treat 30 seconds as a deadline for indexing.
3. Before replaying records, confirm both tenant ID and deduplication key. Both are needed for correct deduplication.
4. Account for source upload retention: uploads are retained for 7 days. Follow the warning above when deciding whether to delete them.

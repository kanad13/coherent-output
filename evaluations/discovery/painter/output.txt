# CSV uploads: a guide for support engineers

An uploaded CSV passes through validation, a queue, and a database writer before its records appear in search. The ingest worker checks the upload, the queue delivers valid records, and the database writer commits them. Search indexes update asynchronously from committed records, so a successful database commit does not mean the records are already searchable. The database is the durable record; the index is a view.

Audit logs record rejection, commit, and index events, which help distinguish where an upload is in this process. Source uploads are retained for 7 days.

WARNING: Never delete source uploads based only on an empty search result.

## How records reach the database and search

The ingest worker receives uploaded CSVs and checks required columns before sending records to the queue. A rejected upload never enters the queue. Valid records include a tenant ID and a deduplication key, which together identify records for deduplication.

Queue messages can be delivered twice and arrive in no guaranteed order. The database writer deduplicates by tenant ID plus deduplication key; neither key alone is sufficient. This combination lets the writer handle repeated deliveries without treating either key alone as a record's identity.

The writer acknowledges a message only after the database commit. A crash before acknowledgment can cause another delivery, even if the commit has already occurred. Another delivery therefore does not by itself show that the first commit failed.

Search indexes update asynchronously from committed records. The typical indexing delay is 30 seconds, but there is no guaranteed upper bound. A record can be committed in the database while still absent from search.

## How to investigate a missing search result

Customer support often mistakes indexing delay for a failed upload. Use audit logs to look for rejection, commit, and index events before drawing that conclusion. A rejected upload never reached the queue; a committed record may still be waiting for indexing. An empty search result alone cannot establish that the upload failed.

Before replaying records, confirm both the tenant ID and the deduplication key. The writer needs their combination to deduplicate correctly. Keep the 7-day source upload retention period in mind during investigation, and follow the warning above when deciding whether to delete an upload.
